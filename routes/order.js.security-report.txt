## Análisis de Vulnerabilidades de Ciberseguridad

### ✅ **Aspectos Positivos**
- Uso correcto de `express-validator` para validaciones
- Implementación de middlewares de autenticación
- Separación adecuada de rutas por nivel de privilegios
- Validación de tipos de datos y rangos

### 🚨 **Vulnerabilidades Identificadas**

#### 1. **Falta de Validación Completa de Entrada**

**Línea 64:** `router.post('/:orderNumber/payment/confirm', OrderController.confirmPayment);`

**Problema:** No hay validación del parámetro `orderNumber` ni del body de la petición.

**Corrección:**
```js
const confirmPaymentValidation = [
  param('orderNumber')
    .matches(/^[A-Z0-9]{8,20}$/)
    .withMessage('Número de pedido inválido'),
  body('paymentId')
    .isAlphanumeric()
    .isLength({ min: 10, max: 100 })
    .withMessage('ID de pago inválido'),
  body('transactionId')
    .optional()
    .isAlphanumeric()
    .isLength({ max: 100 })
];

router.post('/:orderNumber/payment/confirm', confirmPaymentValidation, OrderController.confirmPayment);
```

#### 2. **Validación Insuficiente de Parámetros de Ruta**

**Líneas 63, 67, 72:** Parámetros `orderNumber` e `id` sin validación

**Problema:** Los parámetros de ruta pueden ser manipulados para inyecciones.

**Corrección:**
```js
const { body, param } = require('express-validator');

// Validaciones de parámetros
const validateOrderId = [
  param('id').isMongoId().withMessage('ID de pedido inválido')
];

const validateOrderNumber = [
  param('orderNumber')
    .matches(/^[A-Z0-9]{8,20}$/)
    .withMessage('Número de pedido inválido')
];

// Aplicar validaciones
router.get('/:orderNumber', optionalAuth, validateOrderNumber, OrderController.getOrderByNumber);
router.delete('/:id', auth, validateOrderId, OrderController.cancelOrder);
router.put('/:id/status', adminAuth, validateOrderId, updateStatusValidation, OrderController.updateOrderStatus);
```

#### 3. **Falta de Sanitización XSS**

**Líneas 24-37:** Los campos de texto solo usan `trim()` pero no sanitizan HTML

**Problema:** Posible almacenamiento de scripts maliciosos.

**Corrección:**
```js
const { body, param } = require('express-validator');

const createOrderValidation = [
  // ... otras validaciones
  body('shippingAddress.firstName')
    .trim()
    .escape() // Sanitiza caracteres HTML
    .isLength({ min: 2, max: 50 })
    .matches(/^[a-zA-ZáéíóúÁÉÍÓÚñÑ\s]+$/)
    .withMessage('Nombre contiene caracteres inválidos'),
  body('shippingAddress.lastName')
    .trim()
    .escape()
    .isLength({ min: 2, max: 50 })
    .matches(/^[a-zA-ZáéíóúÁÉÍÓÚñÑ\s]+$/)
    .withMessage('Apellido contiene caracteres inválidos'),
  body('shippingAddress.street')
    .trim()
    .escape()
    .isLength({ min: 10, max: 200 })
    .matches(/^[a-zA-Z0-9áéíóúÁÉÍÓÚñÑ\s\-#.,]+$/)
    .withMessage('Dirección contiene caracteres inválidos'),
  // ... resto de campos con escape() y regex apropiadas
];

const updateStatusValidation = [
  body('status')
    .isIn(['pending', 'confirmed', 'processing', 'shipped', 'delivered', 'cancelled', 'returned'])
    .withMessage('Estado no válido'),
  body('notes')
    .optional()
    .trim()
    .escape() // Sanitizar notas
    .isString()
    .isLength({ max: 500 })
    .matches(/^[a-zA-Z0-9áéíóúÁÉÍÓÚñÑ\s\-.,!?]+$/)
    .withMessage('Las notas contienen caracteres inválidos')
];
```

#### 4. **Falta de Rate Limiting**

**Todas las rutas:** Sin protección contra ataques de fuerza bruta

**Problema:** Posibles ataques DoS y abuso de endpoints.

**Corrección:**
```js
const rateLimit = require('express-rate-limit');

// Rate limiting para creación de pedidos
const createOrderLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutos
  max: 5, // máximo 5 pedidos por IP
  message: 'Demasiados pedidos desde esta IP',
  standardHeaders: true,
  legacyHeaders: false,
});

// Rate limiting para confirmación de pagos
const paymentLimiter = rateLimit({
  windowMs: 5 * 60 * 1000, // 5 minutos
  max: 10, // máximo 10 intentos
  message: 'Demasiados intentos de confirmación de pago'
});

router.post('/', createOrderLimiter, optionalAuth, createOrderValidation, OrderController.createOrder);
router.post('/:orderNumber/payment/confirm', paymentLimiter, confirmPaymentValidation, OrderController.confirmPayment);
```

#### 5. **Falta de Middleware de Manejo de Errores**

**Problema:** Los errores de validación pueden no manejarse correctamente.

**Corrección:**
```js
const { validationResult } = require('express-validator');

const handleValidationErrors = (req, res, next) => {
  const errors = validationResult(req);
  if (!errors.isEmpty()) {
    return res.status(400).json({
      success: false,
      message: 'Errores de validación',
      errors: errors.array().map(err => ({
        field: err.param,
        message: err.msg
      }))
    });
  }
  next();
};

// Aplicar a todas las rutas con validación
router.post('/', createOrderLimiter, optionalAuth, createOrderValidation, handleValidationErrors, OrderController.createOrder);
```
