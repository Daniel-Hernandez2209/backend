## Análisis de Vulnerabilidades de Seguridad

He identificado varias vulnerabilidades críticas en este archivo. Aquí está el análisis detallado:

### 🔴 **CRÍTICO - Configuración TLS Insegura**
**Línea 19:** `rejectUnauthorized: false`

**Problema:** Deshabilita la validación de certificados TLS, permitiendo ataques man-in-the-middle.

**Corrección:**
```js
const createTransporter = () => {
  return nodemailer.createTransporter({
    host: process.env.EMAIL_HOST || 'smtp.gmail.com',
    port: parseInt(process.env.EMAIL_PORT) || 587,
    secure: process.env.EMAIL_PORT === '465', // true solo para puerto 465
    auth: {
      user: process.env.EMAIL_USER,
      pass: process.env.EMAIL_PASS
    },
    tls: {
      rejectUnauthorized: true, // ✅ SIEMPRE true en producción
      minVersion: 'TLSv1.2'     // Forzar versión mínima segura
    }
  });
};
```

### 🔴 **CRÍTICO - XSS (Cross-Site Scripting)**
**Líneas 37, 79, 114, 139, 178, 212:** Interpolación directa sin sanitización

**Problema:** Los datos del usuario se insertan directamente en HTML sin escapar, permitiendo XSS.

**Corrección - Función de sanitización:**
```js
const he = require('he'); // npm install he

// Función para escapar HTML
const escapeHtml = (unsafe) => {
  if (typeof unsafe !== 'string') return unsafe;
  return he.encode(unsafe);
};

// Ejemplo de uso en template:
case 'verification':
  return {
    subject: 'Verificar cuenta - ATHENA BRAND',
    html: `
      <h2 style="color: #161411; margin-bottom: 20px;">¡Hola ${escapeHtml(data.firstName)}!</h2>
      <!-- Resto del template -->
    `
  };
```

### 🟡 **MEDIO - Inyección de URL**
**Líneas 45, 87, 147, 218:** URLs construidas sin validación

**Corrección:**
```js
const url = require('url');

const validateAndBuildUrl = (baseUrl, path, params = {}) => {
  try {
    // Validar URL base
    const base = new URL(baseUrl);
    if (!['http:', 'https:'].includes(base.protocol)) {
      throw new Error('Protocolo no permitido');
    }
    
    // Construir URL segura
    const fullUrl = new URL(path, base);
    
    // Agregar parámetros de forma segura
    Object.keys(params).forEach(key => {
      fullUrl.searchParams.append(key, params[key]);
    });
    
    return fullUrl.toString();
  } catch (error) {
    throw new Error('URL inválida');
  }
};

// Uso en templates:
const verificationUrl = validateAndBuildUrl(
  process.env.FRONTEND_URL,
  '/verificar-cuenta',
  { token: data.verificationToken }
);
```

### 🟡 **MEDIO - Rate Limiting**
**Todo el archivo:** No hay protección contra spam de emails

**Corrección:**
```js
const rateLimit = new Map();

const checkRateLimit = (email, maxEmails = 5, windowMs = 3600000) => { // 5 emails por hora
  const now = Date.now();
  const userLimits = rateLimit.get(email) || { count: 0, resetTime: now + windowMs };
  
  if (now > userLimits.resetTime) {
    userLimits.count = 0;
    userLimits.resetTime = now + windowMs;
  }
  
  if (userLimits.count >= maxEmails) {
    throw new Error('Límite de emails excedido. Inténtalo más tarde.');
  }
  
  userLimits.count++;
  rateLimit.set(email, userLimits);
};

// Aplicar en sendEmail antes de enviar
```
